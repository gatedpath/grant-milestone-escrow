# Contributing

Issues and pull requests are welcome. If something in the README did not work on your machine, say
which step and paste what you saw; that is the most useful report there is.

A pull request that changes a contract comes with a test, and the whole suite stays green. Run it the
way CI does before you open one:

```bash
npm install && npm test
```

Keep attribution lines out of commit messages and pull request descriptions. Name the people who
did the work in the usual way, in the author field, and leave it there.

Security matters go privately, as `SECURITY.md` says, never in a public issue.
